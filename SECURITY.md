# Security Policy

## Reporting a vulnerability

Please **do not** open a public issue. Use GitHub's
[private vulnerability reporting](https://github.com/udsy19/super-paste/security/advisories/new) for this repository.
You'll get a response within a few days, a fix is released as soon as practical, and you'll be credited in the
advisory if you want to be.

Only the latest release receives security fixes; running copies update themselves (see Updates below).

## What Super Paste is

A clipboard manager that runs entirely on your Mac: no accounts, no analytics, no servers operated by the project.
It stores everything you copy, which makes the store itself the sensitive asset, so the design keeps data local,
limits what can reach it, and encrypts anything that leaves.

## Threat model

### Capture

- Content from password managers is never captured (a built-in list of bundle ids, editable by the user), nor
  content marked `org.nspasteboard.ConcealedType`, `TransientType` or `AutoGeneratedType` while those filters are on.
- Captured data lives in `~/Library/Application Support/Super Paste` with the user's normal file permissions. There
  is no additional at-rest encryption beyond FileVault; anyone with access to the user's files has the history.
- The strip can be hidden from screen sharing and recordings (Settings → Privacy).

### Pasting

- Direct paste sends ⌘V to the frontmost app through Accessibility. Super Paste never reads the screen, never
  listens to keystrokes, and only posts that one key event when the user asks for a paste.

### MCP server (off by default)

- Binds to `127.0.0.1` only. Every request must carry a `Host` of `127.0.0.1` or `localhost` with the bound port,
  and any `Origin` must be the server's own; anything else is refused before routing. This defeats DNS rebinding and
  cross-site requests from web pages.
- Access requires a bearer token obtained through OAuth 2.1 (authorization code + PKCE S256, dynamic client
  registration) with explicit user consent on a page the server renders, or a token the user created in Settings
  and that is shown once. Tokens are stored only as hashes. Redirect URIs are limited to `https`, loopback `http`
  and private-use schemes.
- The consent page has no script, a nonce-locked inline style, can't be framed, and may only post back to the
  server and redirect to the client. Pending consents and codes live in memory and expire.
- Request bodies are capped; duplicate `Content-Length` or `Host` headers are rejected. Sessions belong to the
  client that opened them; revoking a client ends its sessions.
- Tools never write to the system clipboard; deletions require a second confirmed call.
- **Out of scope:** what an approved client does with the data it reads. An assistant may send item text to its
  provider; disconnecting the client is the control.
- The stdio bridge only sends its token to loopback `http` or to `https`.

### Sync (off by default)

- A 256-bit master key is generated locally and kept in the macOS Keychain. HKDF-SHA256 derives a sealing subkey
  and a naming subkey. Every file written to the sync folder is AES-256-GCM sealed (`SPS1` header, 12-byte random
  nonce, the header and the file's role as additional authenticated data); blob names are keyed hashes. The folder
  never holds a plaintext value or a value derived without the key.
- Moving the key to another Mac is the user's act (Export Key / Import Key). The key file is a secret: anyone with
  the folder and the key can read the history.
- **Out of scope:** the confidentiality of the folder service's own metadata (file sizes, timestamps, how often
  files change) and the availability of that service.

### Updates (on by default)

- One anonymous HTTPS request to the GitHub API for this repository's latest release, a minute after launch and
  then every six hours. A newer DMG is downloaded, and installed only if its SHA-256 matches the one in the release
  notes, the app inside passes a strict code-signature check and satisfies the designated requirement of the running
  copy (same signing identity), and its bundle id and version are what the release advertises.
- The verified copy is swapped in on quit or when idle. Anything that fails is logged and retried later.
- **Note:** releases are signed with the project's own identity, not notarized by Apple. The one-line installer
  verifies the DMG with `hdiutil verify` but, like any `curl | bash`, trusts GitHub Pages and GitHub Releases over
  HTTPS; read `scripts/install.sh` first if that matters to you.

### URL scheme

- `superpaste://` URLs only open the strip, a search, Settings panes and permission screens. They can't paste,
  read items or change data. Ids in URLs are UUIDs with no other meaning.

## Areas where a report is especially valuable

The MCP server (OAuth, consent page, Host/Origin checks, token handling, the stdio bridge), sync encryption and key
handling, the capture filters for passwords and concealed content, update verification and the swap, and the URL
scheme.
